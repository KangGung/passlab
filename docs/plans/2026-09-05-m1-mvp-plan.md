**함수 목록과 정확한 규칙**
- `today(now=new Date)` → `"YYYY-MM-DD"`(로컬 시각). `addDays(dateStr, n)`. `daysBetween(a, b)` = b − a (일). `dday(examDate, todayStr)` = daysBetween(today, exam) (시험 당일 0).
- `normalizeShort(s)`: 순서대로 (1) 앞뒤·중간 공백 전부 제거 (2) 전각 영숫자·기호 → 반각 (3) 영문 소문자 (4) `·`·`ㆍ`·`•` → `·`, `／` → `/` (5) 괄호와 괄호 안 내용 제거 `(…)`·`[…]` (6) 끝 조사·어미 제거: 은/는/이/가/을/를/의/에/로/으로/이다/입니다/임/함 (한 번만, 뒤에서) (7) 단위 통일: `퍼센트`·`프로`·`％` → `%`, `ug/g`·`㎍/g`·`마이크로그램/g` → `㎍/g`, `밀리그램`→`mg` (8) 숫자 통일: 천 단위 콤마 제거, 소수 끝 0 제거(`1.0`→`1`, `0.010`→`0.01`), `.01`→`0.01`. 반환 문자열.
- `SYNONYMS`: 쌍 배열 `[["메칠","메틸"],["에칠","에틸"],["부칠","부틸"],["프로필","프로필"],["애씨드","산"],["소듐","나트륨"],["포타슘","칼륨"],["징크","아연"],["티타늄디옥사이드","이산화티타늄"],["살리실릭애씨드","살리실산"],["벤조익애씨드","벤조산"],["소르빅애씨드","소르빈산"]]`. `applySynonyms(s)`는 각 쌍의 두 표기를 첫 표기로 통일.
- `gradeShort(q, input)` → `{ correct, stage, nearMiss, blanks, needSelfMark, normalized }`.
  - `q.blanks`가 있으면 `input`은 배열(빈칸별). 각 빈칸을 `accepted`와 대조(같은 4단 규칙), `blanks:[{label, ok, stage}]`, `correct` = 전부 ok.
  - 단일: ① `normalizeShort(input)`이 `answer_text`(각각 normalize) 중 하나와 같으면 `stage:1, correct:true`. ② 아니고 `q.strict_term !== true`면 `applySynonyms` 후 비교 → `stage:2, correct:true`. ③ 아니고 정규화 입력 길이 ≥5(한글)이며 `answer_text` 중 하나와 편집거리 ≤1 → `stage:3, correct:false, nearMiss:true`. ④ 그 외 `stage:4, correct:false, needSelfMark:true`. `q.unit`이 있고 입력에 다른 단위가 있으면 오답(stage 4). `q.grade === "set"`이면 `input`을 `,`·`/`·공백으로 나눠 집합 비교(순서 무관, 전부 있어야 정답).
  - `levenshtein(a,b)` 포함.
- `gradeMcq(q, given)` → `given === q.answer`.
- `attemptScore(att, q)`: 오답 0; 정답이면 conf 2→1.0, 1→0.6, 0→0.15; `att.sec`가 선다 >108 또는 단답 >135면 ×0.8. `self_marked:true`면 0.15(숙달 불인정).
- `questionMastery(atts, q, todayStr)`: `at` 오름차순 정렬 후 최근 3회 가중 1.0/0.6/0.3의 가중 평균×100; 시도 1회면 min(값,70), 2회면 min(값,90); 마지막 시도 후 d일 경과 시 ×max(0.6, 1−0.05d); 시도 0회면 `null`.
- `isMastered(atts, q, todayStr)`: mastery ≥80 AND 최근 2회 정답 AND 그 2회 conf≠0 AND self_marked 아님.
- `topicMastery(topicId, questions, attemptsByQid, todayStr)` → `{ value, n, measuring }`: 해당 topic 문항 중 시도 있는 것들의 mastery 평균 × min(1, n/4); n<4면 `measuring:true`; n=0이면 `{value:null,n:0,measuring:true}`.
- `subjectMastery(subjectId, topics, questions, attemptsByQid, todayStr)`: 세부항목(kind "sub") 토픽 숙달의 `exp_q` 가중 평균, 미시도 토픽은 20으로.
- `applyAttemptToMistake(m, att, q, ctx)` (`ctx = { todayStr, examDate, track:"sprint" }`) → 새 mistake 객체(불변). 규칙: 
  - 오답 또는 (정답 AND conf 0): m 없으면 `{count:1, last, stage:"new", streak:0, next: today+1, interval:1, lastWrong:today, guessed:(conf0정답?1:0), relapse:false, memo:""}`; 있으면 count+1, streak 0, stage가 graduated였으면 `reviewing`+`relapse:true`, 아니면 stage 유지(`reviewing`은 `new`로 내리지 않음), interval 1, next today+1, lastWrong today.
  - 정답·확실/애매(conf≥1, self_marked 아님): streak+1; `new`→`reviewing`; `reviewing`이고 streak≥2 AND daysBetween(lastWrong, today) ≥3 AND (그 2회 정답의 날짜가 서로 다름) → `graduated`, next null. 그 외 next = today + (conf 2 ? interval×2 : 2), interval 갱신(상한 6).
  - 스프린트 D-3 규칙: `dday(examDate, today) ≤ 3`이면 next는 today+1 이하.
- `dueMistakes(mistakes, todayStr)` → stage≠graduated AND next ≤ today 인 qid 배열.
- `seededRandom(seed)` → 0~1 함수(mulberry32). `shuffle(arr, rng)`.
- `buildDiagnostic(questions, topics, blueprint, rng)` → qid 30개: 과목별 3/8/7/12, 그중 단답 1/1/0/4(단답 부족 시 선다로 채우고 `warnings`에 기록), 난이도 2/3/4 ≈ 30/50/20(부족하면 인접 난이도), 같은 세부항목에서 최대 2문항, `exp_q` 큰 토픽부터 1개씩 순회. 반환 `{ qids, warnings }`. 문항 부족 시 있는 만큼 채우고 warning.
- `buildStudySet(questions, opts, attemptsByQid, mistakes, rng)`: `opts = { subject|null, topic|null, type:"all|mcq|short", n:10, mode:"new|due|mixed" }`. `new` = 미시도 우선; `due` = dueMistakes; `mixed` = due 먼저 절반, 나머지 미시도. 같은 문항 중복 없음.
- `judgePass(subjectPoints, blueprint)`: `subjectPoints = {1: n, 2: n, 3: n, 4: n}` → `{ total, pass, failSubjects:[id], bySubject:[{id, points, max, pass_points, pass}] }`. 경계: 총 600 합격, 599 불합격; 과목 39/40 등.
- `diagnosticResult(qids, answers, questions, blueprint, topics)`: `answers = { qid: { correct, conf } }` → `{ bySubject:[{ id, name, n, correct, pct, est_points, max, pass_points, risk }], weakTopics:[{ id, name, n, correct, pct }] (pct 낮은 순, n≥1, 최대 5), est_total, est_note }`. `est_points` = round(max × (선다 정답률×선다 만점 비중 + 0.85×단답 정답률×단답 만점 비중)); 과목에 단답 없으면 선다만. `risk`: pct ≥55 `safe`, 45~55 `warn`, <45 `danger`, n<3 `unmeasured`(진단은 n 작으므로 3). `est_note` = "진단 30문항 기준 초기 추정(신뢰 낮음)".
- `dataCheck(questions, cards, topics)` → `{ total, bySubject:{id:{total, mcq, short, points:{8,12,18}, verified}}, duplicates:[id], badAnswer:[id], badChoices:[id], badWrongExpl:[id], badPoints:[id], missingSource:[id], missingMemory:[id], unknownTopic:[id], cards:{ total, bySubject }, verifiedRatio, ok:boolean }`.
- `dailyPlan(dailyMinutes, ddayNum, dueCount)`: 국면 비중(D-15~11 60/25/15, D-10~6 35/40/25, D-5~3 15/55/30, D-2~1 0/60/40; D≥16은 첫 국면), 문제 시간 = minutes×문제비중 → 새 문항 수 = floor(문제시간/1.7), 오답 재풀이 수 = min(dueCount, floor(minutes×오답비중/1.5)), 카드 수 = floor(minutes×카드비중/0.25). 반환 `{ newQ, review, cards, phase:"early|mid|late|cram" }`.

### Task 8: 검증 패스 (배치 B1~B7 각각, 생성 에이전트와 다른 에이전트)

**역할:** 출제위원장 겸 감수자. 문항을 새로 만들지 않는다. 대상 파일 = Task 7의 해당 배치 파일(`app/data/q_b?_??.js`, `c_b?_??.js`).

**각 문항에 대해**
1. `source`에 적힌 조문·별표·가이드 페이지를 `sources/law/`·`sources/official/guide4/`에서 **직접 열어** 정답·해설의 모든 숫자·용어·주체·기한을 대조한다. 대조 우선순위: 별표 2 한도·연령 조건 → 시행규칙 제12조의2 호별 문구 → 제19조 기재사항·식별번호 → 교육 조문 → 회수·과징금 → 안전성 정보 보고 기한 → CGMP 수치 → 개인정보 유출 신고 → 원료목록 보고 → 알레르기 규정 명칭. 소스에 없는 숫자를 문항이 단정하면 FAIL.
2. 선다형: 5개 보기 각각이 `wrong_option_explanations`대로 실제로 맞고/틀린지, 정답이 2개 이상 되지 않는지, "옳은/옳지 않은" 표시가 있는지, 지문이 모호하지 않은지.
3. 단답형: `answer_text` 허용표기가 충분한지(띄어쓰기·단위·동의어), 반대로 오답을 인정하지 않는지, `strict_term`·`near_miss`가 적절한지.
4. `points`가 배점 의미(8 개념/12 적용/18 사례)에 맞는지, `topic` 코드가 `topics.js`에 있고 내용과 맞는지, `memory_sentence`·`trap`이 사실과 맞는지.
5. 판정: **PASS** → `verified:true, verified_by:"S2-V", verified_at:"2026-09-05"` / **FIX** → 파일 안에서 문항을 수정하고 `history`에 `{date, note:"검증 수정: …"}` 추가 후 PASS 처리 / **FAIL** → 파일에서 제거하고 `UNVERIFIED/{배치}.md`에 문항 전체 JSON과 이유 기록. 같은 논점 어순만 바꾼 중복은 하나만 남기고 나머지 제거(또는 qtype 변형이면 유지).
6. 카드도 같은 방식으로 대조 → `verified:true|false`.
7. 결과를 `docs/verify/{배치}.md`에 표로: `| 문항 ID | 판정 | 대조한 소스(파일:줄) | 수정 내용 | 비고 |` + 요약(PASS/FIX/FAIL 수, PASS율). PASS율 70% 미만이면 생성 규칙의 어느 부분이 약한지 한 줄.
8. `node -e`로 파일 문법·ID 중복·필드 점검 출력을 보고서에.

**하지 말 것:** 검증 없이 verified:true 부여, 소스에 없는 내용으로 "수정", manifest 수정, 다른 배치 파일 수정, 커밋.
