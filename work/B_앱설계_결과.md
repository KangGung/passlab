### B1.3 localStorage(브라우저 저장공간)의 한계와 대응

| 한계 | 내용 | 대응 |
|---|---|---|
| 기기·주소별로 따로 저장 | Mac과 iPhone은 서로 다른 저장공간. 같은 iPhone이라도 Safari 탭과 홈화면 앱은 **저장공간이 별개** `(추정, iOS 동작)` | **주 기기 1대 원칙**(진행기록은 iPhone 홈화면 앱에 쌓기, Mac은 모의고사·빌드용) + JSON 내보내기/가져오기 **병합**(B4.6)으로 왕래 |
| iOS Safari 자동 삭제 | 7일간 사용하지 않은 사이트의 스크립트 저장공간을 지울 수 있음(추적 방지 정책). 저장공간 부족 시에도 정리 대상 `(추정)` | 매일 쓰는 앱이라 실제 위험은 낮음. 그래도 **2일 이상 백업 안 하면 상단 배너 경고** + 결과 화면마다 "백업" 버튼 |
| file://의 공유 저장공간 | Mac에서 로컬 파일로 열면 모든 로컬 HTML이 저장공간을 공유 | 키 이름에 접두어 `sg.v1.` 사용, 호스팅 주소로 옮길 때 1회 내보내기→가져오기 |

### B3.3 핵심 계산식 (숫자로 확정)

모든 값은 앱을 열 때와 세션이 끝날 때 다시 계산한다(저장하지 않고 attempts에서 매번 계산 → 규칙을 바꿔도 과거 기록과 어긋나지 않음).

#### A. 문항 숙달도 `mastery_score` (0~100)

1. 최근 3회 시도만 본다. 가중치: 최근 1.0 / 그 전 0.6 / 그 전 0.3 (합으로 나눔).
2. 시도 1회의 점수 `s`:

| 결과 | 확신도 | s | 이유 |
|---|---|---|---|
| 정답 | 확실 | 1.00 | 안다 |
| 정답 | 애매 | 0.60 | 반쯤 안다 |
| 정답 | **찍음** | **0.15** | 운. **숙달 아님**(사용자 18절) |
| 오답 | (무관) | 0.00 | — |
| 정답인데 시간 초과(선다 >108초, 단답 >135초 = 목표의 1.5배) | — | s × 0.8 | 실전에선 시간이 점수 |

3. `mastery = 100 × Σ(w_i·s_i) / Σ(w_i)`, 시도 1회뿐이면 **상한 70**, 2회면 상한 90 (한 번 맞힌 걸로 "안다"고 믿지 않음).
4. 시간 감쇠: 마지막 시도 후 `d`일 지나면 `× max(0.6, 1 − 0.05·d)` (8일 지나면 60%까지).
5. **숙달(mastered) 판정 = mastery ≥ 80 AND 최근 2회 연속 정답 AND 그 2회 중 찍음 없음.** 숙달 문항은 취약 풀(W)·복습 풀(R)에서 빠지고, 새 문항 풀(N)에 가중치 0.2로만 가끔 나온다("숙지 시 자동 priority 하향", 사용자 12절).
6. 시도 없음 = `null`(화면엔 "미측정").

#### B. 세부항목·과목·전체 숙달

- 세부항목(토픽) 숙달 = 그 토픽에서 시도한 문항들의 mastery 평균 × **표본 보정** `min(1, 시도 문항 수 / 4)`. (문항 4개 미만이면 믿지 않고 "측정 중 n/4" 표시)
- 과목 숙달 = Σ(토픽 숙달 × A1의 토픽별 예상 문항 수) / Σ(예상 문항 수). 시도 없는 토픽은 **20**으로 넣는다(과신 방지용 보수적 기본값 `(추정)`).
- TOTAL MASTERY = Σ(과목 숙달 × 과목 배점) / 1,000 = ①×0.10 + ②×0.25 + ③×0.25 + ④×0.40.

#### C. 예상 점수(/1000)와 오차 밴드

두 추정치를 섞는다.

- **숙달 기반 추정**: 문항 하나를 맞힐 확률 `p` = 선다 `0.20 + 0.80 × (토픽 숙달/100)` (5지선다 찍기 20% 반영), 단답 `0.85 × (토픽 숙달/100)` (정확한 용어 재생이 더 어려움, 0.85 `(추정)`). 과목 예상 점수 = 10 × Σ(블루프린트 문항 수 × p). 4과목 합 = 숙달 기반 총점.
- **모의고사 기반 추정**: 각 모의고사의 **보정 점수** = 원점수 − 8 × (찍어서 맞힌 문항 수) (찍은 문항의 기대 점수는 2점이므로 10−2=8점을 뺌). 최근 것에 가중: 1회 → 그대로, 2회 → 0.7/0.3, 3회 이상 → 0.6/0.3/0.1(가장 최근부터).
- **혼합 비율과 밴드**

| 모의고사 횟수 | 예상 점수 | 오차 밴드(±) | 화면 문구 |
|---|---|---|---|
| 0 | 표시 안 함(진단 30 후엔 숙달 기반만 "초기 추정") | ±120 | "초기 추정 · 신뢰 낮음" |
| 1 | 0.5×모의 + 0.5×숙달 | ±90 | "모의 1회 반영" |
| ≥2 | **0.7×모의(가중) + 0.3×숙달** | ±60 | "모의 n회 반영" |

과목별 예상 점수도 같은 방식으로 따로 계산해 과락 위험에 쓴다.

#### D. PASS READINESS 라벨과 과락 위험

`E` = 예상 점수, `L` = E − 밴드(하한), 과목 예상 비율 = 과목 예상 점수 / 과목 만점.

| 라벨 | 조건(모두 만족) | 아이콘·색 |
|---|---|---|
| **SAFE** | 모의 ≥1회 AND E ≥ 700 AND L ≥ 620 AND 모든 과목 예상 비율 ≥ 50% | ● 파랑 |
| **AT RISK** | E < 600 OR L < 540 OR 어느 과목이든 예상 비율 < 40% | ✖ 주황 |
| **BORDERLINE** | 그 외 전부(모의 0회는 최대 BORDERLINE) | ▲ 황토 |

과목별 과락 위험(대시보드 4줄 옆 배지): 예상 비율 ≥ 55% **안전 ●** / 45~55% **주의 ▲** / < 45% **위험 ✖** / 시도 문항 < 8 → "미측정". 기준 40%에 5~15%p 안전 마진을 둔 이유: 밴드가 ±60~120점이라 40% 근처는 실제로 반반이기 때문.

#### E. 적응형 출제 비중 50/30/20 (QUICK 10/20, 오늘의 문제)

세션 N문항을 세 풀에서 뽑는다: **W 취약 50% / R 복습 due 30% / N 새 문항 20%**(반올림, N=10이면 5/3/2).

- **R(복습)**: `next_review ≤ 오늘`인 오답노트 문항. 기한 지난 순. 같은 변형 그룹(`vg`)에 최근 2일 안 본 형제 문항이 있으면 **형제로 교체 출제**(같은 개념을 다른 방식으로).
- **W(취약)**: 숙달 < 60인 토픽의 문항 + 문항 mastery < 50인 문항(R에 든 것 제외, 숙달 문항 제외). 우선순위 점수
  `P = 3×(1 − mastery/100) + 2×[3일 내 오답] + 1.5×min(연속 오답,3)/3 + 1×[마지막 확신도 애매·찍음] + 1×[평균 시간 > 목표 1.5배] + 1.5×중요도(H 1 / M 0.5 / L 0) + 1×(토픽 예상 문항 수 / 최대 예상 문항 수)`
  → P 상위 2×필요 수 중에서 무작위로 뽑는다(매번 같은 순서 방지).
- **N(새 문항)**: 한 번도 안 푼 문항. 토픽 예상 문항 수(배점)로 가중 추첨 → 비중 큰 4과목·빈출 토픽이 먼저 나온다. 숙달 문항은 가중치 0.2로 "유지 확인용" 편입.
- **부족 시 채우기 순서**: R 부족 → W에서, W 부족 → N에서, N 부족 → 가장 오래전에 푼 문항. 첫날처럼 기록이 없으면 자연히 N 100%가 된다.
- 같은 문항은 하루 2번 안 나온다(R의 due 재시험 제외). 한 세션에서 한 과목이 60%를 넘지 않게 상한.

#### F. 진단시험 30문항 조합 규칙

블루프린트 ①3 ②8 ③7 ④12(=10/25/25/40 비율), 단답 ①1 ②1 ③0 ④4(총 6=20%), 난이도 2:3:4 = 30:50:20 `(추정)`, 토픽은 A1 예상 문항 수 상위부터 1개씩 커버(빈출 토픽을 한 번씩 찍어봄). 결과 화면: 과목별 정답률, 초기 추정 점수(±120), 취약 토픽 Top5(정답률 오름차순, 시간 내림차순), "먼저 공부할 영역" = 과목 배점 × (1 − 정답률)이 가장 큰 과목의 최약 토픽.

#### G. 모의고사 100문항 조합 규칙

실제 배열을 따른다 `(추정: 1~80 선다, 81~100 단답, 각 블록 안은 과목 순)`: 선다 ①7 ②20 ③25 ④28, 단답 ①3 ②5 ③0 ④12. 선택은 (1) 모의고사에 나온 적 없는 문항 우선 (2) 토픽별 예상 문항 수에 비례 (3) 난이도 30:50:20 (4) `verified:false` 문항은 전체의 30% 이하로 제한. 재고 부족 시 화면에 "④ 단답 12 필요 / 9 보유 → 3문항은 기출제 문항으로 채움" 경고 후 진행(막지 않음).

### B4.6 단답형 입력 — 한국어 자판(IME) Enter 문제

증상: iPhone·Mac 한국어 자판은 마지막 글자를 **조합 중**인 상태에서 Enter를 누르면, 마지막 글자가 빠진 값이 제출되거나 Enter가 두 번 발생한다.

| 대책 | 구현 메모 |
|---|---|
| Enter는 보조, **[답 입력 완료] 버튼이 주** | 버튼은 44px 이상, 입력창 바로 아래 |
| Enter 처리 시 조합 중이면 무시 | `keydown`에서 `e.isComposing || e.keyCode === 229`면 return. iOS 일부 버전은 이 플래그가 거짓이므로 **제출을 0ms 뒤로 미뤄** 입력창의 최종 값을 읽음(`setTimeout(…,0)`) |
| 입력창 속성 | `autocomplete="off" autocorrect="off" autocapitalize="none" spellcheck="false" enterkeyhint="done"` (자동 수정이 성분명을 바꾸는 것 방지) |

## B5. 오답노트 로직

### B5.1 단계 규칙 (new → reviewing → graduated)

| 단계 | 들어오는 조건 | 나가는 조건 | 화면 배지 |
|---|---|---|---|
| **new** | 처음 오답 **또는** 정답이지만 확신도 "찍음"(운으로 맞힘 = 모르는 것) | 재시험 1회 정답(찍음 아님) → reviewing | "새 오답" 주황 ✗ |
| **reviewing** | new에서 1회 정답 / graduated에서 재오답(재발) | 아래 졸업 조건 충족 → graduated / 오답 → streak 0, 간격 1일로 리셋(단계는 유지) | "복습 중" 황토 ▲ |
| **graduated** | **연속 2회 정답(둘 다 찍음 아님) AND 마지막 오답 후 3일 경과 AND 2회 중 최소 1회는 오답 다음 날 이후의 세션** | 재오답 → reviewing + `relapse`+1 (우선순위 ×1.5) | "졸업" 파랑 ✓ |

- 00 파일의 예시 "연속 2회 정답 + 마지막 오답 후 7일"에서 **3일로 줄인 이유**: D-15 스프린트에서 7일이면 한 문항이 복습 기회를 1번밖에 못 얻고 D-3 이후 졸업이 불가능해짐. 정규 트랙(`track:"regular"`)은 7일을 그대로 쓴다.
- "같은 세션 안에서 곧바로 다시 맞힌 것"은 streak에 넣지 않는다(방금 본 정답을 기억한 것뿐). 그래서 조건에 "오답 다음 날 이후 세션 1회"를 넣었다.
- 졸업해도 기록은 남고, FINAL CRAM에서는 제외된다(아는 것 반복 금지 — 사용자 27절). D-1에 "졸업 문항 1줄 암기만 훑기" 목록을 따로 제공한다(3분짜리).

### B5.2 오답 이유 4분류 ↔ 사용자 8분류 ↔ 처방

첫 탭은 4개(속도), 두 번째 탭(선택, M3)에서 세부를 고른다. "찍었다"는 이유가 아니라 **확신도**에서 이미 받았으므로 이유 목록에서 뺐다.

| 4분류(버튼) | 사용자 8분류 매핑 | 앱이 즉시 하는 처방 | 통계에서 많이 나오면 |
|---|---|---|---|
| **몰라서** `unknown` | 몰랐다 | 연결 카드 전부 펼침 + 박스① 자동 편입, 다음날 **변형 문항** 예약 | 해당 토픽 "개념 구멍" → WEAKNESS ATTACK 상위, 클로드 설명 요청 권장 |
| **헷갈려서** `confused` | 헷갈렸다 / 숫자를 잊었다 / 용어를 혼동했다 / 보기 2개에서 고민했다 | `trap`과 `why_wrong`(내가 고른 보기의 오답 이유)을 강조 표시 + **compare형 카드**(A vs B) 편입 | LAW & NUMBERS 세션 추천, 비교표 카드 생성 프롬프트 제안 |
| **실수** `slip` | 문제를 잘못 읽었다 | "옳지 않은 것은?" 같은 부정 어구를 노랗게 표시하는 **읽기 보조** 켜기 제안, 단계는 reviewing으로 바로(개념은 아는 것) | 모의고사에서 5% 넘으면 "문제 끝까지 읽기" 체크리스트 |
| **시간부족** `time` | (시간 초과·미답) | 모의고사에서 미답/시간초과 자동 태깅. 해당 qtype 평균 시간 표시, 다음 모의에서 "72초 알림" 옵션 | 유형별 시간 통계 → 시간이 긴 qtype(계산·표 유형) 연습 세트 |
| (기타) | 기타 | 메모 입력 | — |

### B5.3 약점 진단(과목·세부항목·유형별)

| 지표 | 계산 | 표시 조건 |
|---|---|---|
| 정답률 | c / n (찍어서 맞힌 건 정답에서 뺀 "실질 정답률"도 병기) | n ≥ 4 |
| 평균 시간 | secSum / n, 목표(선다 72초·단답 90초) 대비 % | n ≥ 4 |
| 숙달 | B3.3-B | — |
| **약점 점수** | `(1 − 실질 정답률) × 예상 문항 수 × (1 + 0.5×[평균시간 > 목표 1.5배]) × (1 + 0.3×[최근 3일 오답 있음])` | 상위 5개를 "취약 세부항목 Top5"로. n < 4는 "측정 중" |
| 유형(qtype)별 | 위 지표를 qtype 축으로 | 단답형·계산형·case형은 따로 카드로 노출 |
| 이유 분포 | 4분류 비율(최근 7일) | 원형 아닌 **가로 막대 4개**(색+아이콘) |

### B5.4 오답 상세 화면의 데이터 매핑(사용자 16절 → 스키마)

내 답 `attempts.given` / 정답 `answer`·`answer_text` / 왜 틀렸는가 `attempts.why` + `why_wrong[given]` / 핵심 개념 `cards[].front·back` / 정답이 되는 이유 `explanation` / 다른 보기가 틀리는 이유 `why_wrong` / 시험 함정 `trap` / 1줄 암기 `memo1` / 공식 근거 `source` / 관련 문제 같은 `vg`·같은 `cards` / 다음 복습일 `mistakes.next` / [다시 풀기] = 단일 문항 세션.

### B6.1 Leitner 5박스 vs SM-2 단순화

| 기준 | Leitner 5박스 | SM-2 단순화(Anki식) |

### B6.2 규칙(스프린트 / 정규)

| 박스 | 스프린트 간격 | 정규 간격 | 의미 |
|---|---|---|---|
| ① | 0일(같은 세션 끝 또는 당일 재노출) | 1일 | 새 카드·틀린 카드 |
| ② | 1일 | 3일 | |
| ③ | 2일 | 7일 | |
| ④ | 4일 | 14일 | |
| ⑤ | 7일(스프린트에선 사실상 "시험 전 1회 확인") | 30일 | 숙달 |

- 판정 버튼 3개: **몰라요** → 박스① (`lapses`+1) / **애매** → 같은 박스 유지, due +1일 / **알아요** → 박스 +1.
- 새 카드는 박스①로, 하루 도입 수는 B3.3-I 공식(400장·9/8 시작 → 약 50장/일). 도입 순서: `importance` H → 취약 토픽 카드 → `short_prone` → 나머지.

- 카드 → 문항 역방향: 카드 "몰라요" 시 `related` 문항의 mastery에 −10 보정(다음 계산 때 W 풀에 들어오게), 단계는 바꾸지 않음.
- 하루 카드 상한: 가능 시간의 25%(60분 → 15분 ≈ 50~60장). 넘치면 due 오래된 것·중요도 H 우선, 나머지는 다음 날로 밀림(밀린 수를 홈에 표시).
